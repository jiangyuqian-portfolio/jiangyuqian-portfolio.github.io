案例 02 · 实验分析

实验结果不显著，新落地页还要不要上线

一家电商网站用 22 天、约 29 万用户测试新版落地页，结果不显著。这里记录我怎么先确认实验本身没问题，再用置信区间和功效分析，把“不显著”变成一个能执行的上线判断。

新页面的相对提升上限只有 0.8%，低于 2% 的上线门槛。想测出 1% 的提升还要再跑近半年，不划算。

实验本身可信两组各占 50.0%，SRM 检验 p = 0.84。3,893 名用户两个页面都看过，已整组剔除。
新页面没有提升，值得上线的提升也基本可以排除差异 −0.14 个百分点，95% 置信区间 [−0.38, +0.09]。这个样本量足以测出 2.8% 以上的提升（功效 80%），这次没有测到。
换几种方式检查，结论都成立没有新奇效应；按工作日 / 周末、访问时段分群都不显著；换一种清洗方式，结论也一样。

1 · 先检查实验本身

数据能不能信？分组有没有出问题？

按设计，对照组看旧页面，实验组看新页面，每个用户只分一次组。原始数据 294,478 行，检查时发现两个问题，查下去其实是同一件事：

发现数量说明
分组和页面对不上3,893 行例如对照组用户看到了新页面
用户重复出现3,894 人每人出现 2 次
两者的关系100%对不上的记录全部来自重复用户，这些人新旧页面都看过

这些用户两个页面都看过，没法归到任何一组，所以我把这 3,893 人整组剔除（占 1.3%）。剔除前先确认会不会带来偏差：他们的记录在“对照组 / 实验组 × 旧页面 / 新页面”四种组合里各有 1,900–2,000 条，分布很均匀，更像是一个对两组影响相同的分流 bug，剔除不会偏向哪一组。另有 1 名重复用户的两条记录分组都对，保留了他最早的一条。

常见的做法是只删掉对不上的那一行，但这样会留下看过两个页面的人。后面的稳健性检查里两种做法都算了，结论一致。

清洗后，对照组 143,293 人，实验组 143,398 人。用卡方检验对比 50/50 的设计比例，p = 0.84，没有样本比例失衡（SRM）。这一步要是没通过，后面的结果都不能用。

SQL 要点：识别污染用户并整组剔除
DROP TABLE IF EXISTS ab_clean;
CREATE TABLE ab_clean AS
WITH bad AS (   -- 任何一条记录分组与页面不一致的用户
  SELECT DISTINCT user_id FROM ab_raw
  WHERE ("group" = 'control') != (landing_page = 'old_page')),
r AS (
  SELECT a.*, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY timestamp) AS rn
  FROM ab_raw a
  WHERE user_id NOT IN (SELECT user_id FROM bad))
SELECT user_id, timestamp, date(timestamp) AS day, "group", landing_page, converted
FROM r WHERE rn = 1;

2 · 新页面有没有效果

新页面的转化率比旧页面高吗？

旧页面转化率 12.02%（17,220 / 143,293），新页面 11.87%（17,025 / 143,398）。双样本比例 z 检验 p = 0.23；如果只检验“新页面更好”这一个方向，p = 0.88。

不显著，不代表没有结论

只说“p > 0.05，不显著”还不够。不显著可能是新页面真的没用，也可能是样本太少看不出来。要区分这两种情况，得看两样东西：

  • 置信区间：相对提升的 95% 置信区间是 [−3.2%, +0.8%]，新页面最好的情况也只比旧页面高 0.8%。
  • 最小可检测效应（MDE）：在 5% 显著性和 80% 功效下，这个样本量能可靠检测出 0.34 个百分点（相对 2.8%）以上的提升。
假设业务方认为，相对提升至少要到 2% 才值得承担新页面的开发和维护成本。置信区间上限 0.8% 远低于 2%，所以可以比较有把握地说：新页面达不到上线标准。
Python 要点：z 检验、置信区间与 MDE
from scipy import stats
import numpy as np

pc, pt = xc / nc, xt / nt                       # 两组转化率
p_pool = (xc + xt) / (nc + nt)
z = (pt - pc) / np.sqrt(p_pool * (1 - p_pool) * (1/nc + 1/nt))
p_two_sided = 2 * (1 - stats.norm.cdf(abs(z)))

se = np.sqrt(pc*(1-pc)/nc + pt*(1-pt)/nt)       # 置信区间用非合并标准误
ci = (pt - pc - 1.96*se, pt - pc + 1.96*se)

# 最小可检测效应：alpha = 0.05（双侧），power = 0.8
z_a, z_b = stats.norm.ppf(0.975), stats.norm.ppf(0.80)
mde = (z_a + z_b) * np.sqrt(pc*(1-pc) * (1/nc + 1/nt))

3 · 这个结论稳不稳

会不会是时间、人群或数据处理方式造成的假象？

效果随时间稳定，没有新奇效应

新页面刚上线时，用户可能出于新鲜感多点几下，过一阵就消退了，这就是新奇效应。我把实验分成前后两半：前半段差异 +0.02 个百分点，后半段 −0.29，两者差别不显著（p = 0.20）。下图是逐日累计的效果，置信区间随样本增加逐渐收窄，但一直包含 0。

这张图也能看出“中途偷看”的风险：单日差异在 −0.94 到 +1.36 个百分点之间来回波动，如果哪天看到一个好看的数字就宣布胜利，很容易误判。这次 22 天里，累计 p 值最低也只有 0.13。逐日 p 值在这里只用来描述过程，没有用来决定何时停止；如果真要边测边看，应该事先用序贯检验。

分群：没有哪类用户明显更喜欢新页面

按工作日 / 周末和访问时段拆成 6 个分群，都不显著。周末和凌晨时段新页面略差一点（p = 0.06 和 0.09），但同时检验 6 个分群，本来就容易碰巧出现接近显著的结果，做 Bonferroni 校正后分别是 0.38 和 0.53。这些可以留作下一轮实验的线索，不能当结论。

换一种清洗方式，结论不变

如果只删掉对不上的记录再按用户去重（更常见、但不够严谨的做法），差异是 −0.16 个百分点，p = 0.19；完全不清洗，差异是 −0.15 个百分点。三种处理方式结论一致。

4 · 要不要继续测

如果再多测一段时间，会不会测出效果？

这个实验每天大约进来 13,000 名新用户。按 12% 的基线转化率，测出不同幅度的提升分别需要多少天：

这次 22 天大约能测出 3% 的提升。测 2% 要 45 天，测 1% 要 178 天。而置信区间已经说明真实提升最多 0.8%，就算再测半年，最好的结果也只是确认一个不够上线的小提升。所以我建议停止测试，把流量留给下一个改版方案。

5 · 结论之后做什么

"不上线"之后，团队下一步做什么？下次实验怎么设计得更好？

这次实验本该提前定好的规则

看什么指标、什么情况下上线，应该在实验开始前写清楚，免得结果出来后再找理由。按这次的情况，规则大致是：

类型指标作用
主指标转化率决定上不上线
护栏指标客单价、跳出率、退款率确保新页面没有"转化持平、但别的变差"。本数据集没有这些字段，真实业务中必须看
有效性检查两组人数比例（SRM）、每个用户只看到一个页面不通过就先修实验，不看结果
上线规则相对提升 ≥ 2%，p < 0.05，且护栏指标没有变差三条同时满足才上线
停止规则样本量达到预先计算的数量才看结论，中途不因为某天数字好看就停避免"中途偷看"带来的误判

行动清单

优先级行动负责团队具体做什么
P1停止测试，全部用户回到旧页面产品新页面达不到上线标准，继续测只会占用流量
P1修复分流 bug工程 + 数据排查为什么 3,893 名用户被记录了两次、看到了两个页面；之后每次实验上线时自动跑 SRM 检查和"一人一组"检查，不通过就报警
P2复盘新页面，提出下一版假设产品 + 设计 + 数据逐项列出新页面改了什么，结合用户访谈判断哪些改动可能有负面影响。周末和凌晨时段新页面略差（未达显著），可以作为下一版的观察点
P2设计下一轮实验数据见下表：先算好样本量和时长，再开始

下一轮实验设计

设计要素方案
假设针对复盘找出的一个具体改动，比如"缩短首屏文案、突出主按钮，能提高转化率"。一次只验证一个主要改动，结果才说得清
最小有意义的提升相对提升 3%（基线 12.0%，即约 +0.36 个百分点）。比这更小的提升，不值得承担改版成本
样本量与时长每组约 12.9 万人，按每天约 1.3 万新用户计算，需要约 20 天，覆盖完整的周末周期
分流50/50，按用户编号分流，保证同一个用户始终看到同一个页面
决策按上面事先定好的上线规则判断，结论出来前不改规则
一句话向业务方汇报：新页面没有带来提升，最好的情况也只有 0.8%，低于 2% 的上线门槛，建议不上线。另外分流有 bug，需要先修好，再用约 20 天测下一版改动。

方法与局限

环节做法
数据清洗SQL：识别分组与页面不一致的记录，整组剔除受污染用户，按用户去重
实验有效性样本比例失衡（SRM）卡方检验，逐日流量检查
主检验双样本比例 z 检验（合并标准误），卡方检验交叉验证；差异的 95% 置信区间（非合并标准误）
功效分析当前样本量下的最小可检测效应；检测 1%–5% 提升所需样本量与天数
稳健性前后半段对比（新奇效应）、累计效果曲线、分群检验与 Bonferroni 校正、不同清洗方式的敏感性分析

局限

  • 只有“是否转化”一个指标，没有客单价、跳出率等护栏指标。真实业务中，即使转化率持平，也要确认新页面没有损害其他指标。
  • 数据集不含用户来源、设备、国家等字段，分群只能按时间维度做。
  • 2% 的上线门槛是假设值，实际应由开发成本和预期收益共同决定。
  • 这是一个公开的教学数据集，适合演示完整的分析流程，不代表某家具体公司的情况。
