案例 01 · 用户与经营分析

增长见顶之后，这家电商平台应该先修物流

Olist 是巴西的一个电商平台。我用它公开的近 10 万笔订单回答了四个问题：增长靠什么，用户为什么不回来，差评从哪来，资源有限时先改什么。

数据　Olist 公开数据集，8 张关联表 时间窗　2017.01 – 2018.08 工具　SQL（SQLite，窗口函数 / CTE）、Python（pandas、matplotlib）
97,905
有效订单
94,703
独立用户
R$ 1,345 万
GMV（巴西雷亚尔）
72
商品品类

核心结论

增长全靠拉新，2018 年已经见顶2018 年 1–8 月 GMV 同比增长 138%，几乎都来自买家数增加（+138.6%），客单价和人均订单数基本没动。进入 2018 年后，月订单量一直停在 6–7 千单。
用户很少回来，主要是品类原因，体验也有影响复购率 3.0%，去掉同一天拆单的情况后只有 2.1%。平台卖的多是耐用品，复购本来就低；但首单遇到延迟的用户，复购率比按时送达的低约 30%。
差评主要出在配送延迟上延迟订单只占 6.7%，却带来了 32.6% 的 1–2 分差评。晚到 7 天以上的订单，69.8% 打了 1 星；按时订单只有 6.6%。

1 · 增长从哪里来

平台这两年增长得怎么样？增长靠的是买家变多，还是每个人买得更多？

把 GMV 拆成 买家数 × 人均订单数 × 客单价，比较 2018 年和 2017 年同期（1–8 月）：

增长几乎全部来自新买家。客单价一直在 R$ 137 上下，人均订单数接近 1，也就是说平台每多卖一单，基本都要多拉来一个新客。2018 年订单量不再上涨，拉新的效果在变弱。

SQL 要点：用 LAG() 计算月环比
WITH m AS (
  SELECT month, COUNT(*) AS orders, COUNT(DISTINCT user_id) AS buyers,
         SUM(gmv) AS gmv, SUM(gmv) / COUNT(*) AS aov
  FROM v_orders GROUP BY month)
SELECT *, 100.0 * (gmv / LAG(gmv) OVER (ORDER BY month) - 1) AS gmv_mom_pct
FROM m ORDER BY month;

2 · 用户为什么不回来

买过一次的用户，有多少会再回来？复购低是品类决定的，还是体验造成的？

94,703 个用户里，只有 2,874 人下过两单以上，复购率 3.0%。再细看，其中 31% 的"第二单"和首单是同一天下的，大多是一次购物拆成了两单。去掉这部分，真实复购率是 2.1%。按首单月份分组看留存，首单后每个月回来的用户都不到 1%。

先按首单品类拆开看，差别很明显：

箱包、家居、床品这类会反复添置的东西，复购率是电子产品、游戏机的 2–3 倍。手机、电脑配件、手表买一次能用很久，短期内不回来很正常，这是整体复购低的主要原因。

体验的影响，我一开始没看出来。最先用"下过两单以上"来算，首单打差评和打好评的用户复购率几乎一样（2.9% 对 3.1%）。后来发现这个算法有两个问题：同日拆单被算成了复购；最近才下首单的用户，还没来得及回来。改用真实复购率，并且只看 2018 年 3 月前首单、至少有 6 个月观察期的用户，差别就出来了：

首单情况用户数真实复购率
评分 4–5 分42,8423.00%
评分 1–2 分7,1952.22%
按时送达51,2442.91%
延迟送达3,5802.04%

首单延迟的用户，复购率低了约 30%。复购低主要是品类结构决定的，但配送做得好不好，也会影响一部分用户回不回来。

SQL 要点：用户 ID 的坑，以及用 ROW_NUMBER() 算真实复购
-- customer_id 每笔订单都会新生成一个，用它算复购率结果是 0%
-- 必须用 customer_unique_id 代表"一个真实的人"
WITH r AS (
  SELECT user_id, order_id, purchase_ts,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY purchase_ts) AS k
  FROM v_orders),
f AS (  -- 每个用户的首单；只保留至少有 6 个月观察期的用户
  SELECT user_id, order_id, purchase_ts AS first_ts
  FROM r WHERE k = 1 AND purchase_ts < '2018-03-01'),
rep AS (  -- 首单 1 天以后是否再次下单（排除同日拆单）
  SELECT f.user_id,
         MAX(julianday(o.purchase_ts) - julianday(f.first_ts) >= 1) AS repeated
  FROM f JOIN v_orders o USING (user_id)
  GROUP BY f.user_id)
SELECT CASE WHEN v.review_score >= 4 THEN '4-5 分'
            WHEN v.review_score = 3  THEN '3 分' ELSE '1-2 分' END AS first_score,
       COUNT(*) AS users,
       100.0 * SUM(rep.repeated) / COUNT(*) AS true_repeat_pct
FROM f JOIN rep USING (user_id) JOIN v_review v USING (order_id)
GROUP BY first_score;

用户分群：RFM 需要调整

RFM 按最近一次购买（R）、购买次数（F）和消费金额（M）给用户分群。但这里 97% 的用户只买过一次，F 基本没有区分度。所以我把买过两次以上的用户单独归为"复购用户"，其余用户按 R（180 天内有没有买过）和 M（是否高于中位数 R$ 89.8）分成四组。

"沉睡高价值"用户最值得花力气召回：人数占 28%，贡献了 46% 的 GMV，人均消费 R$ 232，但平均已经 339 天没下单了。

3 · 差评从哪里来

如果只能改一件事来提升体验，应该改什么？

把实际送达日期和平台承诺的预计送达日期对比，95,560 笔已签收订单里有 6.7% 晚到了。晚得越久，差评越多：

差评是延迟本身带来的吗？

也可能是另一种情况：延迟订单刚好集中在偏远的州或难配送的品类，这些订单本来评分就低。为了排除这一点，我在每个"州 × 品类"组合内部比较按时和延迟订单的评分，再按延迟订单数加权平均。

控制州和品类后，延迟订单平均仍然低 1.99 分，和不控制时的 2.02 分几乎一样。255 个可比较的组合里，每一个都是延迟订单评分更低。所以评分下降确实和延迟有关，不是地区或品类带来的。

SQL 要点：分层对比，控制州和品类
WITH cell AS (
  SELECT state, category,
         AVG(CASE WHEN late_days <= 0 THEN review_score END) AS on_time,
         AVG(CASE WHEN late_days >  0 THEN review_score END) AS late,
         SUM(late_days > 0) AS n_late
  FROM v_delivery
  GROUP BY state, category
  HAVING SUM(late_days > 0) >= 5 AND SUM(late_days <= 0) >= 5)
SELECT COUNT(*) AS cells,
       SUM((on_time - late) * n_late) / SUM(n_late) AS weighted_score_gap,
       100.0 * SUM(on_time > late) / COUNT(*)      AS cells_late_worse_pct
FROM cell;

延迟集中在哪里

时间上，集中在大促之后。2017 年 11 月黑五当月延迟率 12.3%，2018 年 2 月和 3 月分别是 14.0% 和 18.7%，这几个月的平均评分也是全期最低。三个月的订单只占 21.7%，延迟订单却占了 48.5%。

地区上，里约（RJ）最需要优先处理。东北部几个州延迟率更高，但订单不多。里约是第二大市场，12,172 单，延迟率 12.0%，差不多是圣保罗（SP，4.4%）的 3 倍。

建议

按投入产出排序。影响估算用了一个简化假设：延迟订单如果按时送达，评分会和同州同品类的按时订单一样。

1. 大促前做物流产能预案

黑五和 2018 年 2–3 月的延迟订单接近总数的一半，而延迟既拉低评分，也影响复购。大促前按预测单量提前准备仓储和运力，大促期间把预计送达日期设得保守一些，对可能晚到的订单提前通知用户。

如果延迟订单都能按时送达，平均评分可以从 4.16 升到约 4.29，1–2 分差评减少约 27%（12,228 → 约 8,870 条）。
2. 优先改善里约的配送

里约单量大、延迟率高，改善一个州就能覆盖很多订单。可以先从承运商和仓库覆盖范围查起。

里约延迟率降到圣保罗水平，延迟订单从 1,456 单降到约 540 单，相当于全平台延迟订单减少约 14%。
3. 定向召回"沉睡高价值"用户，用 A/B 测试验证

复购低主要是品类结构造成的，大范围发券意义不大。更划算的做法是只针对这 26,679 名用户，优先推家居、床品、箱包这类复购高的品类，同时留一组不推送作为对照。

效果要等实验结果才能估算。留对照组，是为了不把本来就会回来的用户算成召回效果。

4 · 落到业务上

这些发现要变成哪些行动？谁来做，怎么判断做成了？

指标拆解：增长从哪来，问题在哪

把 GMV 一层层拆开，对比 2017 年和 2018 年同期（1–8 月）。2018 年的 52,336 个买家里，98.7% 是第一次下单，从 2017 年回来的老客只有 663 人。同一时期，延迟率从 3.4% 涨到 7.6%，平均评分从 4.23 降到 4.14。

放在一起看：平台靠拉新把规模做大了一倍，但物流没跟上。延迟变多，评分下降，新客的首单体验变差，回来的人很少，只能继续花钱拉新。所以我认为现阶段最该先解决的是履约，而不是营销。

行动方案

按优先级排列，综合考虑前面估算的影响大小和实施难度（难度是我的主观判断）。

优先级建议负责团队第一步（30 天内）成功指标

怎么验证改进有没有用

物流改进没办法像网页一样随机分给每个用户，但可以按州做试点，借用案例 02 的实验思路来评估：

设计要素方案
试点范围选 3 个延迟率高的州（如里约、巴伊亚、圣埃斯皮里图）先上物流预案，其余州保持现状作为对照
观察窗口下一次大促前 4 周到大促后 4 周
主指标延迟率
次要指标1–2 分差评占比、90 天复购率
护栏指标每单物流成本，确保改善不是靠无限加钱换来的
评估方法双重差分（DID）：比较试点州和对照州在大促前后的变化差，剔除"大促本身"对所有州的共同影响
推广条件试点州延迟率相对对照州多下降 3 个百分点以上，且每单物流成本增幅在可接受范围内，再推广到全国
一句话向业务方汇报：平台增长全靠拉新，但物流没跟上，延迟订单带来了三分之一的差评，首单延迟的用户复购率也低 30%。建议先在 3 个州试点大促物流预案，看延迟率和差评率有没有改善，有效再推广。

局限

  • 分层对比排除了州和品类的干扰，但这仍是观察数据，卖家、价格等因素没有全部控制，影响估算只能作为方向参考。
  • 数据截止到 2018 年 8 月，越晚首单的用户观察期越短，留存会偏低，所以比较复购率时只取观察期满 6 个月的用户。
  • 延迟分析只包含已签收且有评价的订单。另有约 0.8% 的评价同时关联了多个订单，对结论影响很小。
  • 数据里没有浏览、加购等行为日志，做不了下单前的转化漏斗。
