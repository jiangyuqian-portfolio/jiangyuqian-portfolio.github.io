案例 01 · 用户与经营分析

增长见顶后，电商平台应优先改善物流

基于巴西电商平台 Olist 近 10 万笔公开订单数据，围绕四个问题展开分析：增长来源、复购偏低的原因、差评成因，以及资源有限时的改进优先级。

数据　Olist 公开数据集，8 张关联表 时间窗　2017.01 – 2018.08 工具　SQL（SQLite，窗口函数 / CTE）、Python（pandas、matplotlib）
97,905

94,703

R$ 1,345 万

核心结论

增长依赖拉新，2018 年进入平台期2018 年 1–8 月 GMV 同比增长 138%，主要来自买家数增长（+138.6%），客单价与人均订单数基本持平。2018 年起，月订单量稳定在 6–7 千单。
复购率低，主因是品类结构，履约体验亦有影响复购率 3.0%，剔除同日拆单后为 2.1%。平台以耐用品为主，复购需求天然较低；同时，首单延迟用户的复购率比按时送达用户低约 30%。
配送延迟是差评的主要来源延迟订单占 6.7%，却贡献了 32.6% 的 1–2 分差评。延迟超过 7 天的订单中 69.8% 为 1 星，按时订单仅为 6.6%。

1 · 增长从哪里来

平台增长表现如何？增长来自买家数量，还是单个买家的购买量？

把 GMV 拆成 买家数 × 人均订单数 × 客单价，比较 2018 年和 2017 年同期（1–8 月）：

增长几乎全部来自新买家。客单价稳定在 R$ 137 左右，人均订单数接近 1，订单增长基本依赖新客获取。2018 年订单量趋于平稳，获客的边际效果正在减弱。

SQL 要点：用 LAG() 计算月环比
WITH m AS (
  SELECT month, COUNT(*) AS orders, COUNT(DISTINCT user_id) AS buyers,
         SUM(gmv) AS gmv, SUM(gmv) / COUNT(*) AS aov
  FROM v_orders GROUP BY month)
SELECT *, 100.0 * (gmv / LAG(gmv) OVER (ORDER BY month) - 1) AS gmv_mom_pct
FROM m ORDER BY month;

2 · 复购为何偏低

首购用户中有多少会回购？复购偏低源于品类还是体验？

94,703 名用户中，2,874 人下单两次及以上，复购率 3.0%。其中 31% 的"第二单"与首单在同一天，多为拆单；剔除后真实复购率为 2.1%。同期群分析显示，首单后各月的回购用户占比均不足 1%。

按首单品类拆分，复购率差异明显：

箱包、家居、床品等需要持续添置的品类，复购率是电子产品、游戏主机的 2–3 倍。手机、电脑配件、手表等耐用品购买周期较长，这是整体复购率偏低的主要原因。

履约体验的影响需要正确的口径才能识别。以"下单两次及以上"计算时，首单差评与好评用户的复购率几乎相同（2.9% 对 3.1%）。该口径存在两个问题：同日拆单被计为复购；近期首单用户的观察期不足。改用真实复购率，并限定为 2018 年 3 月前首单、观察期不少于 6 个月的用户后，差异显现：

首单情况用户数真实复购率
评分 4–5 分42,8423.00%
评分 1–2 分7,1952.22%
按时送达51,2442.91%
延迟送达3,5802.04%

首单延迟用户的复购率低约 30%。品类结构决定了复购的整体水平，履约体验则进一步影响用户是否回购。

SQL 要点：用户 ID 的坑，以及用 ROW_NUMBER() 算真实复购
-- customer_id 每笔订单都会新生成一个，用它算复购率结果是 0%
-- 必须用 customer_unique_id 代表"一个真实的人"
WITH r AS (
  SELECT user_id, order_id, purchase_ts,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY purchase_ts) AS k
  FROM v_orders),
f AS (  -- 每个用户的首单；只保留至少有 6 个月观察期的用户
  SELECT user_id, order_id, purchase_ts AS first_ts
  FROM r WHERE k = 1 AND purchase_ts < '2018-03-01'),
rep AS (  -- 首单 1 天以后是否再次下单（排除同日拆单）
  SELECT f.user_id,
         MAX(julianday(o.purchase_ts) - julianday(f.first_ts) >= 1) AS repeated
  FROM f JOIN v_orders o USING (user_id)
  GROUP BY f.user_id)
SELECT CASE WHEN v.review_score >= 4 THEN '4-5 分'
            WHEN v.review_score = 3  THEN '3 分' ELSE '1-2 分' END AS first_score,
       COUNT(*) AS users,
       100.0 * SUM(rep.repeated) / COUNT(*) AS true_repeat_pct
FROM f JOIN rep USING (user_id) JOIN v_review v USING (order_id)
GROUP BY first_score;

用户分群：RFM 需要调整

RFM 模型依据最近一次购买（R）、购买频次（F）和消费金额（M）对用户分群。本数据中 97% 的用户仅购买一次，F 缺乏区分度。因此将购买两次及以上的用户单列为"复购用户"，其余用户按 R（180 天内是否购买）和 M（是否高于中位数 R$ 89.8）划分为四个象限。

"沉睡高价值"用户是召回的重点：用户占比 28%，贡献 46% 的 GMV，人均消费 R$ 232，平均已 339 天未购买。

3 · 差评成因

若只能优先改进一项体验，应选择什么？

对比实际送达日期与预计送达日期，95,560 笔已签收订单中 6.7% 延迟送达。延迟时间越长，差评越集中：

差评是否由延迟本身导致？

另一种可能是，延迟订单集中于偏远州份或配送难度较高的品类，而这些订单的评分本身偏低。为排除该干扰，在每个"州 × 品类"组合内部比较按时与延迟订单的评分，并按延迟订单数加权平均。

控制州与品类后，延迟订单评分平均仍低 1.99 分，与未控制时的 2.02 分基本一致；255 个可比组合中，延迟订单评分均更低。由此可见，评分下降与延迟直接相关，并非地区或品类差异所致。

SQL 要点：分层对比，控制州和品类
WITH cell AS (
  SELECT state, category,
         AVG(CASE WHEN late_days <= 0 THEN review_score END) AS on_time,
         AVG(CASE WHEN late_days >  0 THEN review_score END) AS late,
         SUM(late_days > 0) AS n_late
  FROM v_delivery
  GROUP BY state, category
  HAVING SUM(late_days > 0) >= 5 AND SUM(late_days <= 0) >= 5)
SELECT COUNT(*) AS cells,
       SUM((on_time - late) * n_late) / SUM(n_late) AS weighted_score_gap,
       100.0 * SUM(on_time > late) / COUNT(*)      AS cells_late_worse_pct
FROM cell;

延迟集中在哪里

时间上，延迟集中在大促之后。2017 年 11 月黑五当月延迟率为 12.3%，2018 年 2 月、3 月分别为 14.0% 和 18.7%，对应月份的平均评分为全期最低。这三个月的订单占比 21.7%，延迟订单占比却达 48.5%。

地区上，里约（RJ）应优先改善。东北部部分州延迟率更高，但订单量较小。里约为第二大市场（12,172 单），延迟率 12.0%，约为圣保罗（SP，4.4%）的 3 倍。

建议

按投入产出排序。影响估算基于以下简化假设：延迟订单若按时送达，其评分与同州同品类的按时订单一致。

1. 大促前做物流产能预案

黑五及 2018 年 2–3 月的延迟订单接近总量的一半，而延迟同时影响评分与复购。建议大促前依据预测单量提前扩充仓储与运力，大促期间适当放宽预计送达日期，并对可能延迟的订单主动告知用户。

若延迟订单全部按时送达，平均评分预计由 4.16 升至约 4.29，1–2 分差评减少约 27%（12,228 → 约 8,870 条）。
2. 优先改善里约的配送

里约订单量大、延迟率高，改善单一地区即可覆盖大量订单。可优先排查承运商表现与仓储覆盖范围。

里约延迟率降到圣保罗水平，延迟订单从 1,456 单降到约 540 单，相当于全平台延迟订单减少约 14%。
3. 定向召回"沉睡高价值"用户，用 A/B 测试验证

复购偏低主要源于品类结构，大范围发券效果有限。建议仅针对 26,679 名沉睡高价值用户，优先推荐家居、床品、箱包等高复购品类，并保留对照组。

效果需通过实验评估；设置对照组可避免将自然回购计入召回效果。

4 · 业务落地

分析结论如何转化为行动？由谁负责，如何衡量成效？

指标拆解：增长从哪来，问题在哪

逐层拆解 GMV，对比 2017 年与 2018 年同期（1–8 月）。2018 年 52,336 名买家中，98.7% 为首次下单，2017 年的老客回购仅 663 人。同期延迟率由 3.4% 升至 7.6%，平均评分由 4.23 降至 4.14。

综合来看：平台依靠拉新实现规模翻倍，但履约能力未能同步提升。延迟增加导致评分下降、新客首单体验变差，回购用户少，平台只能持续投入获客。因此，现阶段应优先解决履约问题，而非加大营销投入。

怎么验证改进有没有用

物流改进无法像网页改版那样按用户随机分组，但可以按州试点，参照案例 02 的实验思路评估效果：

设计要素方案
试点范围选 3 个延迟率高的州（如里约、巴伊亚、圣埃斯皮里图）先上物流预案，其余州保持现状作为对照
观察窗口下一次大促前 4 周到大促后 4 周
主指标延迟率
次要指标1–2 分差评占比、90 天复购率
护栏指标每单物流成本，避免以成本大幅上升换取时效改善
评估方法双重差分（DID）：比较试点州和对照州在大促前后的变化差，剔除"大促本身"对所有州的共同影响
推广条件试点州延迟率相对对照州多下降 3 个百分点以上，且每单物流成本增幅在可接受范围内，再推广到全国
一句话向业务方汇报：平台增长依赖拉新，但履约能力未能跟上：延迟订单贡献了约三分之一的差评，首单延迟用户的复购率低 30%。建议先在 3 个州试点大促物流预案，以延迟率和差评率衡量效果，验证有效后再推广。

局限

  • 分层对比控制了州与品类，但本分析基于观察数据，卖家、价格等因素未完全控制，影响估算仅作方向性参考。
  • 数据截至 2018 年 8 月，近期首单用户观察期较短、留存偏低，因此复购对比仅纳入观察期满 6 个月的用户。
  • 延迟分析仅包含已签收且有评价的订单；约 0.8% 的评价关联多个订单，对结论影响较小。
  • 数据不含浏览、加购等行为日志，无法分析下单前的转化漏斗。
